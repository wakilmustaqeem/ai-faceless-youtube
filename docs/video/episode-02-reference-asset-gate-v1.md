## Reference rules

- Use clean, well-lit neutral character references.
- Keep identity references separate from environment references.
- Do not replace approved references with drifted generated frames.
- Use reference images to preserve character and scene continuity across shots.
- For multi-character shots, maintain separate approved references for each person.
- All generated frames must be compared against the approved reference before becoming a new production asset.

Current reference-driven generation guidance supports this approach: consistent character workflows benefit from high-quality neutral references, and character plates can reinforce identity across different angles and scenes. citeturn0search0turn0search6

## Hard rejection

Reject an asset if:
- face identity drifts;
- body proportions change;
- wardrobe changes without story reason;
- 2040 hardware appears in 2027;
- displays become floating;
- teleport looks like fantasy magic;
- character becomes an avatar/cartoon;
- UI contradicts the locked story;
- destination year is unclear.

## Approval sequence

Reference → Owner review → Lock → Shot generation → Frame QA → Animation → Continuity QA.

No final generation approval before this gate passes.
